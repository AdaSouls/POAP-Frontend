# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

The AdaSouls POAP portal — a React/CRACO frontend, currently on the `feature/production` branch. This is the frontend half of a Cardano Catalyst-funded project (Fund 11, project #1100234) that is mid-migration from a Milkomeda C1 (Cardano EVM sidechain, now shut down) architecture to **Midnight** (IOG's ZK privacy blockchain). The Compact smart contract and indexer this app talks to live in the sibling repo `../POAP-Midnight`, maintained by a different developer — **all project context (frontend and backend) is tracked from this repo only**; `POAP-Midnight` is kept as a clean, undocumented clone (no `CLAUDE.md`, don't add one there). The "Backend reference" section below is a standing summary of that repo so you don't need to open it for routine frontend work — if it goes stale, refresh it by reading `../POAP-Midnight` directly rather than guessing.

**`README.md` in this repo is stale** — it describes an earlier Ethereum/MetaMask/WalletConnect-only architecture (`cd App`, `ethers.js`, generic EVM wallets). The actual code on this branch has already moved to Midnight + Lace wallet integration (`src/midnight/`, `src/jsx/contexts/drawer/useMidnight.js`, `laceWallet.jsx`). Don't trust the README's described stack or directory layout (there is no `App/` subdirectory — this repo's root *is* the CRA app); trust `package.json` and the actual `src/` tree instead.

This app is a fork of a commercial React admin-dashboard template ("qash" — see `package.json`'s `name` and dependencies like `apexcharts`, `millify`, `sweetalert2`), repurposed as the POAP portal. Expect template-era UI scaffolding (charts, dashboard widgets) unrelated to POAP/Midnight to still be present.

## Architecture

### Three separate backends, one app

This portal talks to three independent systems, configured via separate env vars (`.env.example`):
1. **Souls/Collections REST API** (`REACT_APP_API_BASE_URL`) — `src/services/collection.service.ts`, `token.service.ts`. Plain fetch-based CRUD for "souls"/collections, unrelated to the blockchain layer.
2. **Midnight** (`REACT_APP_MIDNIGHT_CONTRACT_ADDRESS`, `REACT_APP_MIDNIGHT_INDEXER_API_URL`) — the POAP contract + indexer from `../POAP-Midnight`. This is the active development focus.
3. **Cardano** (`REACT_APP_BLOCKFROST_*`, `REACT_APP_MNEMONIC_DEVNET`) — Blockfrost + `lucid-cardano` (imported directly from a CDN URL in `drawer.provider.jsx`: `https://unpkg.com/lucid-cardano@0.10.7/web/mod.js`) for the legacy/parallel Cardano-native soulbound-token path. `REACT_APP_POAP_CONTRACT_ADDRESS_HARDHAT` is a leftover from the pre-Midnight EVM/Hardhat setup.

### Midnight integration (`src/midnight/`)

- **`providers.ts`** — `connectToLace()` discovers and enables the Midnight Lace wallet via `window.midnight.mnLace` (the `DAppConnectorAPI`), polling for up to 5s and enforcing a compatible connector API version (`1.x`). `buildProviders()` assembles the full Midnight JS provider set (private state via `levelPrivateStateProvider`, ZK config via `FetchZkConfigProvider` pointed at `/midnight/poap`, proof provider, indexer-backed public data provider, and a wallet/midnight provider pair that bridges transaction signing back through the Lace wallet). `getOrCreatePrivateState()` generates a random 32-byte secret key on first connect and persists it via the private state provider from then on.
- **`contract.service.ts`** — `PoapContractService` wraps `findDeployedContract` (mirrors the Midnight `bboard` reference example's pattern) and exposes one typed async method per contract circuit (`claim`, `createEvent`, `mintTo`, `burn`, `revealPrivateMetadata`/`revealPrivateTokenMetadata`, `pause`/`unpause`, `registerIssuer`/`deactivateIssuer`). `getCallerPkHex`/`getHolderPkHex` are derived locally rather than called as circuits — see `witnesses.ts`'s `deriveCallerPk`/`deriveHolderPk` comments for why. `state$` is a combined RxJS observable of public ledger state + this browser's private token state.
- **`contract/managed/poap/`** — compiled contract module (`contract/index.js`/`index.d.ts`/`index.js.map`), **manually copied** from `../POAP-Midnight/contracts/src/managed/poap/`. The matching per-circuit `.zkir`/`.bzkir` and `.prover`/`.verifier` files live separately under `public/midnight/poap/{zkir,keys}/` (fetched at runtime by `FetchZkConfigProvider`, see `providers.ts`'s `POAP_ZK_CONFIG_BASE_PATH`) — also a manual copy from the backend, gitignored there since it's generated locally via `compactc`/`npm run compact`. There is no sync script for any of this; if the backend contract changes and is recompiled, both locations must be refreshed by hand.
- **`src/jsx/contexts/drawer/useMidnight.js`** — the React-facing hook. Caches the derived caller public key in `localStorage`, keyed by **both** the wallet's `coinPublicKey` and the contract address (`adasouls:midnight:callerPkHex:<coinPublicKey>:<contractAddress>`) after the first `getCallerPkHex()` call, specifically to avoid re-deriving it. Scoped by wallet so switching wallets in the same browser can't serve a stale pk cached from a different wallet (found 2026-08-14); scoped by contract address so **redeploying the contract** can't serve a stale pk cached from the previous deployment either (found 2026-08-19 — `getOrCreatePrivateState` generates a fresh `local_sk()` per contract address, so `caller_pk()` genuinely differs across deployments even for the same wallet; without this, "My Events" silently shows nothing right after a redeploy). Composed into the app-wide `DrawerContext` in `drawer.provider.jsx` alongside `useCardano`.

Several comments in `providers.ts` and `contract.service.ts` flag **unverified-against-a-live-node** assumptions (the ledger↔zswap transaction bridging round-trip, the shape of a value-returning circuit call's result). Treat these as open risk areas, not settled behavior, when working in this area — check whether they've since been verified before relying on them.

### Webpack/CRACO shims (`craco.config.js`, `src/shims/`)

Midnight's JS packages are a mix of WASM-bindgen CJS builds and ESM builds that don't survive CRA's default webpack config unmodified. `craco.config.js` adds:
- WASM support (`asyncWebAssembly`, `.wasm` resolve extension, exclude `.wasm` from the default asset/resource rule)
- `Buffer` polyfill via `ProvidePlugin` (Midnight/crypto libs assume Node's `Buffer` global)
- Four `resolve.alias` overrides forcing specific packages to their CJS build instead of the ESM build webpack would otherwise pick, each with a shim in `src/shims/`: `isomorphic-ws`, `@midnight-ntwrk/midnight-js-network-id`, `@midnight-ntwrk/ledger`, `@midnight-ntwrk/onchain-runtime`. Read the comments at the top of `craco.config.js` and in each shim file before touching any of this — the reasons are subtle (static export analysis on `module.exports` reassignment patterns) and easy to accidentally re-break.
- `@midnight-ntwrk/zswap` is handled differently: `providers.ts` bypasses the resolver entirely with a plain `require()` rather than an aliased import, for the same category of reason.

### Frontend structure

- `src/jsx/pages/` — route-level pages (`router.jsx` wires them up); `src/jsx/drawer/views/` — slide-out drawer forms (create event/issuer/POAP/soul, Lace wallet connect).
- `src/jsx/contexts/drawer/` — the main app state: `drawer.provider.jsx` composes `useCardano` + `useMidnight` into one reducer-backed context (`DrawerContext`/`DrawerDispatchContext`).
- `src/jsx/contexts/user-roles/` — separate context for role-based UI (organizer vs. attendee, etc.).

## Backend reference (`../POAP-Midnight`, maintained separately)

Owned and developed by a teammate working in that repo directly. Read-only context for frontend work — don't edit that repo, and don't reintroduce a `CLAUDE.md` there. Grant history and full rationale: `../POAP-Midnight/docs/CHANGE-REQUEST.md` and `docs/PROOF-OF-PRIOR-WORK.md`.

**Repo layout**: `contracts/` (Compact contract + compiled artifacts + Jest simulator tests), `indexer/` (custom Node/TS indexer), `scripts/deploy.ts` + `scripts/verify-env.sh`, `docker-compose.devnet.yml` (local devnet), `docs/environment.md` (authoritative local setup guide — compactc invocation, proof-server params, devnet ports, Lace wallet), `docs/compact-research.md` (Compact 0.5.0 language notes).

**The contract (`contracts/compact/poap.compact`)**: one Compact contract (Midnight's public/private ledger duality replaced the four old Solidity contract variants — `PoapPublic`/`Poap`/`SoulboundPoap`/`ConsensualSoulboundPoap` — with a single unified one). Public ledger: `totalSupply` (Counter), `tokenOwner`/`tokenEvent`/`tokenIssuer`/`burnedTokens` (keyed by `tokenId`), `tokenMetadataURI`/`tokenPrivateMetadataCommit`/`tokenRevealedMetadata` (per-token metadata, keyed by `tokenId` — see below), `events`/`issuers` (keyed by `Bytes<32>` id), `eventRevealedMetadata` (keyed by `eventId`, populated by `revealPrivateMetadata`), `eventHolderToken` — a `(holderPk, eventId) → tokenId` index preventing the same wallet claiming the same event twice, `isPaused`, `adminPk`. Identity has no accounts: a caller's *global* identity is `caller_pk()` (used for admin/issuer/organizer checks), derived from a client-held `local_sk()` witness. There's also `holder_pk(issuerId)` — a *per-issuer* pseudonym (different, uncorrelatable value per issuer for the same wallet) used everywhere a holder's token ownership is checked (`tokenOwner`, `eventHolderToken`, `mintTo`'s recipient, `burn`) — exported as `getHolderPk`, distinct from the also-exported `getCallerPk`. Witnesses (private, client-side): `local_sk`, `store_token` — implemented in `contracts/src/witnesses.ts` and mirrored on the frontend side in `src/midnight/witnesses.ts`, so the two must stay in sync by hand.

As of the 2026-08-18 update (`05d0e8f`), **every claim mints a brand-new token** — the old "one token per issuer, updated on repeat claims" model is gone. `claim(eventId, isSoulbound)` (renamed from `claimOrUpdate`) mints a token scoped to `(holderPk, eventId)`; calling it again for an event this wallet already claimed reverts on-chain ("Wallet already claimed this event") — there is no reconciliation/backfill path anymore. `updateToken`/`reconcileToken` and the `get_my_token_for_issuer`/`store_attendance`/`has_attended` witnesses were removed entirely; the private-state cache (`src/midnight/witnesses.ts`) is now purely a same-browser convenience list, not load-bearing for contract logic — it only ever contains tokens *this browser* self-claimed, never organizer push-mints (see below). Tokens carry their own metadata now: `tokenMetadataURI` (inherited from the event at `claim()` time, or set independently per recipient via `mintTo`) and `tokenPrivateMetadataCommit`/`revealPrivateTokenMetadata` (same commit-reveal pattern as the event-level fields, applied per token). `mintTo(eventId, recipientPk, tokenMetadataURI, tokenPrivateMetadataCommit)` (organizer/admin push-mint) now takes two more params — the contract stores exactly what's passed, there's no on-chain fallback to the event's own metadata, so callers that want to mirror it must pass `ev.metadataURI` explicitly. `burn(tokenId)` now also accepts admin or the token's own issuer/organizer as caller, not just the owner (revocation power for misissued/revoked credentials).

`createEvent` is fully permissionless (the old `is_active_issuer` gate is gone — anyone's `caller_pk()` becomes `organizer`; the `issuers` registry is opt-in "verified organizer" metadata only, not an authorization check) and takes two more params: `metadataURI` (off-chain JSON pointer — name/description/image — the event-level default every token inherits at claim time) and `privateMetadataCommit` (a `persistentCommit` digest; all-zero means no private part). `computePrivateMetadataCommit(value, rand)` / `revealPrivateMetadata(eventId, value, rand)` implement that field's commit-reveal: anyone who knows `(value, rand)` can reveal — knowing the opening is itself the authorization — which publishes `value` into `eventRevealedMetadata` permanently (commit-reveal hides *when* it becomes public, not whether).

**The indexer (`indexer/`)**: WS client (`client.ts`) → subscription (`subscriptions.ts`) → `parser.ts` (deserializes the hex `ContractState` via the compiled contract's own `ledger()` function, diffs successive states) → `poap-state.ts` (applies the diff) → `db.ts`/Postgres (`db/migrations/001_init.sql`: `issuers`, `events`, `tokens`, `indexer_cursor` for resume-on-restart) → Express REST API (`api/routes/{events,tokens}.ts`) — this is what the frontend's `REACT_APP_MIDNIGHT_INDEXER_API_URL` points at. `/events` and `/tokens` responses include `metadataURI`; `/tokens` responses also include the token's own `tokenMetadataURI`/`tokenPrivateMetadataCommit`. The ledger-side `tokenEvent` field is exposed via the API/DB as `firstEventId`/`first_event_id` (kept for API stability even though a token now maps to exactly one event, not just its *first* one). `GET /api/tokens/:id/attendance` returns `410 Gone` — the concept no longer exists. The API supports CORS via an env-gated allowlist.

**Local devnet** (`devnet.yml`, repo root — **the only devnet file now**; the old-generation `docker-compose.devnet.yml` was removed 2026-08-13 and merged in): four services — `node` (`midnightntwrk/midnight-node:0.22.5`, `:9944`), `indexer` (`midnightntwrk/indexer-standalone:4.3.3`, GraphQL API on `:8088`), `proof-server` (`midnightntwrk/proof-server:8.1.0`, `:6300`), and `poap-pg` (Postgres 15, `:5434` — the indexer app's own business-data DB, unrelated to the Midnight SDK generation). Start with `docker compose -f devnet.yml up -d` from inside `../POAP-Midnight`. `docs/environment.md` has a hard requirement worth knowing even from the frontend side: contract artifacts must be compiled against the exact `public_params.bin` extracted from the matching `proof-server` image — a mismatched proof-key/params pairing fails proof verification at runtime, not at compile time, which can look like a frontend bug when it's actually a backend build issue. **Redeploying the contract changes its address, which changes what `local_sk()` a given browser generates for it** (`getOrCreatePrivateState` in `providers.ts` keys private state per contract address) — this in turn changes `caller_pk()`, so a *cached* caller-pk from a previous deployment (see `useMidnight.js` below) silently goes stale after every redeploy, not just after switching wallets.

**Sync point with this repo**: three separate manual-copy locations, all sourced from `../POAP-Midnight/contracts/src/managed/poap/` — none of this propagates automatically when the backend recompiles: `src/midnight/contract/managed/poap/contract/` (`index.js`/`index.d.ts`/`index.js.map` — the compiled contract module `contract.service.ts` imports), `public/midnight/poap/zkir/` and `public/midnight/poap/keys/` (per-circuit `.zkir`/`.bzkir` and `.prover`/`.verifier` files, fetched at runtime by `FetchZkConfigProvider` for in-browser proving — gitignored on the backend side, generated locally via `cd contracts && npm run compact`, so these have to be hand-delivered, not just `git pull`-ed). If claims/mints start failing with ABI-shaped errors, or proofs fail to verify, after the other developer changes the contract, this is the first thing to check. Last verified 2026-08-18 against backend commit `05d0e8f` ("Mint a fresh token per claim, add per-token metadata, allow revocation") — full resync done: contract artifacts + zkir + keys copied, `witnesses.ts`/`contract.service.ts` updated to the new `claim`/`mintTo`/`revealPrivateTokenMetadata` signatures, and the "my POAPs" UI (`mySubscriptions.jsx`, `poapCard.jsx`, `my-tokens.ts`) rewritten to read tokens from the indexer by per-issuer holder pk rather than from local private state — required because organizer push-mints (`mintTo`) no longer have any reconciliation path to become visible otherwise. `myPendingApprovals.jsx` was removed as part of that rewrite: the concept it existed for (a token minted to you that your browser doesn't know about yet) is now just handled automatically by the indexer-sourced read.
